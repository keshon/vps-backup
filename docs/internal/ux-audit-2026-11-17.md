# CLI and setup audit, 17 November 2026

Scope: installation, recovery-key handoff, interrupted setup, ordinary commands,
app changes, automation output and documentation. Triggered by an actual terminal
session in which an unconfigured installation could neither be rerun nor initialized.

| Observed problem | Change | Validation |
| --- | --- | --- |
| Install without a bundle succeeds; rerun refuses | Installer updates a recognized runtime and resumes setup; install-only is explicit | Install/update on disposable Linux CI runner; ownership and rollback tests |
| `init` sounds like initial setup but needs existing settings | `setup` owns the whole onboarding flow; `init` stays advanced with a setup hint | Missing-config and setup retry tests |
| Setup creates config before remote init fails, then refuses retry | Saved credentials are reused; remote config is probed before init; existing repository is opened | Network failure/retry, existing repository and actual gateway tests |
| The key and destination config are indistinguishable in help | Prompts explain where `.bundle.json` comes from and what setup creates | Missing-key, empty-file, copied-key and wrong-key tests |
| Main help is a flat list and calls the command `-c` | Fixed program name and task-grouped help | CLI parser and help tests |
| `check`, `doctor`, `status` have unclear roles | Primary names are `verify`, `preflight`, `status`, with explicit local/cloud scope | Alias compatibility and terminal/JSON tests |
| Raw JSON and long silent uploads obscure progress | Terminal summaries; stage progress on stderr; JSON remains available | Notification fixtures and output-mode tests |
| Editing app lists requires finding JSON fields | `apps` shows the list; `apps --select` confirms and preserves a private previous copy | Selection cancellation and consistent-config guards |
| A flag works only before the command | Config and JSON flags work in both positions | Parser tests for both forms |
| Server commands default to client.json | Defaults follow the command's role | Server config selection test |

Remaining limits: discovery can identify common SQLite extensions and paired
`wal.log`/`snapshot-*.json` stores, but cannot prove every app's persistence model.
The operator still reviews container writers and mounts outside selected folders.
This revision does not install a gateway route, provision cloud credentials, add
automatic retention, or change existing n8n schedules. An integrity check is not
a substitute for reviewing an application's restored files and database records.
